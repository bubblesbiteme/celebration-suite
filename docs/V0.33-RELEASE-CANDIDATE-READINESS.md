# Celebration Suite v0.33.0 — Release Candidate Readiness & End-to-End Reliability

## Purpose

v0.33.0 is a stabilization release. It does not redesign the planner or client portal. It strengthens supportability, diagnostics, integration visibility, and release validation around the direct-fork architecture established in prior releases.

## Platform Admin Account Health

The Platform Admin console now loads a tenant health summary from `platform-health.mjs`. Each tenant receives a health score and warnings based on:

- usable license state
- unresolved runtime errors
- open support tickets
- failed webhooks in the last seven days
- stale users
- orphaned event/client links
- orphaned client access records
- orphaned inventory reservations
- reservation quantities larger than inventory owned
- orphaned documents
- orphaned floor plans
- orphaned inspiration boards/items
- configured integrations

Platform Admin can also export a tenant support snapshot containing the core tenant-scoped records needed for troubleshooting. The export action is logged in `platform_admin_actions`.

## Planner Account Health

`integration-health.html` gives a planner a safe tenant-scoped view of:

- license state
- connected integrations
- API key count
- webhook status and recent failures
- unresolved recent browser/runtime errors
- event count
- active user count

The page is linked from White-Label Settings and the API/Webhook Integration Center.

## Release-Candidate Validation

The release adds two repeatable validation tools:

- `tools/audit-release-candidate.mjs` — validates critical page contracts, event-context handoffs, shared planner/client data sources, branding, Account Health, and admin troubleshooting controls.
- `tools/smoke-critical-pages.mjs` — validates critical page controls and parses every inline script used by the core planner/client/admin surfaces.

The existing runtime-global, planner/client collaboration, client portal parity, branding, and preflight audits remain required.

## Database

No new database migration is required. v0.33.0 uses the observability and admin-action tables introduced in migrations 0023 and 0024.
